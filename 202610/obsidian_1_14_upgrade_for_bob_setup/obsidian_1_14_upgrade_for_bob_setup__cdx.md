# Obsidian 1.12 → 1.14 for Bryan: useful upgrades around the Bob workflow

Independent research by **cdx**, 2026-10-18. No other report or findings from this swarm were consulted.

The highest-value changes for your setup are better access to Markdown outside the vault, smoother navigation, searchable settings, and improved image viewing. Colored highlights are a useful small addition to authored notes. Bases Kanban deserves a bounded experiment as a library browser; it is a poor fit as a replacement for Bob's task system. Native iOS capture is a separate, conditional opportunity, not a new Mac capture panel.

This assessment uses official release notes and documentation, your current bob-cli and bob-plugins sources, tracked Bob configuration in chezmoi, and audited SASE memory. I did not inspect your running Mac installation, installed theme/snippets, enabled community-plugin inventory, or vault size. Accordingly, the feature availability is verified against releases, while installed-version and compatibility claims remain explicitly conditional. No app settings, plugins, task data, or sync configuration were changed.

Your remembered version jump is plausible. The public **1.13 release was July 30, 2026**, represented by build 1.13.4; public **1.14 was October 5, 2026**, represented by build 1.14.4. Those are the intervening releases reviewed here, including their maintenance fixes. Early-access entries explain when individual features first appeared; their presence in those entries does not mean you now need Catalyst to use the public release. [Public 1.13 notes](https://obsidian.md/changelog/2026-07-30-desktop-v1.13.4/), [public 1.14 notes](https://obsidian.md/changelog/2026-10-05-desktop-v1.14.4/).

**Check both application version and installer version before judging what the upgrade enabled.** Settings → General displays both. A current in-app version can coexist with an older installer. The 1.14 release specifically requires the latest installer for its external Markdown opening integration, and Quick Look also requires it. If needed, download and reinstall Obsidian, then try a harmless Markdown file outside Bob. I have not performed this installation. [Version information](https://obsidian.md/help/settings), [external files and Quick Look](https://obsidian.md/help/manage-notes).

Several things you may see discussed as “new Obsidian features” predate this jump: the CLI itself, corner-drag image resizing, automatic attachment cleanup, and Bases search were already in public 1.12. The notable CLI refinement in **1.12.7** is a separate executable that makes terminal interactions faster, with a new installer required. That refinement may still be new to your machine if its old app or installer was an earlier 1.12 build. [Public 1.12](https://obsidian.md/changelog/2026-02-27-desktop-v1.12.4/), [1.12.7](https://obsidian.md/changelog/2026-03-23-desktop-v1.12.7/).

**The most interesting new workflow is reading repository Markdown directly.** SASE reports, repository READMEs, and design notes need not be copied into Bob just to get comfortable Markdown rendering. External files stay at their original locations, open in the current Obsidian window, and resolve local links/images relative to their directory. Outline and Outgoing links are supported. Finder's Space-key preview also works with Obsidian closed. [External-file documentation](https://obsidian.md/help/manage-notes).

For you, that means a document can remain owned and versioned by its research or code repository while being read in Obsidian. Start with “Open file from outside the vault…”; making Obsidian the default `.md` application is optional and may be less attractive if your existing editor association is useful. Opening a file this way does not establish that Bob task commands, Dataview, or vault-wide link discovery will treat it as part of Bob. I found no basis to promise those integrations. Treat it initially as document viewing/editing, and keep any edits in the originating repository's workflow. This is an inference about the appropriate use, not a tested Bob integration.

**Navigation improvements have a better effort-to-benefit ratio than new dashboards.** In 1.14.2, fuzzy matching stopped falling back to a simpler algorithm above 10,000 files; 1.14.3 improved speed and ranking of word-initial matches. The public release also adds full-path matching and more useful folder exclusion in sidebar searches. [1.14.2](https://obsidian.md/changelog/2026-09-15-desktop-v1.14.2/), [1.14.3](https://obsidian.md/changelog/2026-09-29-desktop-v1.14.3/), [public 1.14](https://obsidian.md/changelog/2026-10-05-desktop-v1.14.4/).

You frequently move among daily notes, area/project notes, reference bundles, and archives. Try the existing quick switcher and link suggestions on familiar long names before adding or tuning another navigation plugin. In File Explorer search, experiment with a negative folder term such as `-done` when browsing active material, checking which paths it actually excludes. That is an interactive view filter, not a change to Bob's task queries or the tiered review walk. I have not counted your files, so the 10,000-file threshold is conditional; the general ranking and sidebar changes still merit a trial.

**Bases can organize a reference collection, but the unit is a file.** Native 1.14 Kanban groups files into columns. Moving a card changes the grouping property; when grouped by `file.folder`, it moves the file itself. Formula grouping disables card/column dragging and note creation from columns, while group ordering and visibility remain available through the menu. Groups also became collapsible across other layouts. [Kanban documentation](https://obsidian.md/help/bases/views/kanban), [public 1.14](https://obsidian.md/changelog/2026-10-05-desktop-v1.14.4/).

The distinction matters twice for Bob. First, one area note contains many task rows, with different lanes and dependency reasons. A card for that file cannot express their individual state. Second, current `bob ref` applies reading-task precedence and conflict handling that a simple frontmatter-status board would bypass. Even a board that appears visually correct today may lag a reading-task change tomorrow. Creating a second authored `status` or `today` field merely to make a board work would add competing state to maintain.

A useful experiment is instead a **reference browser grouped by kind or parent**, with title and source link visible. Filter to reference Markdown files, start with all groups visible (including missing values), and use a grouping formula such as `note.ref_type` if preventing accidental card movement is desirable. This limits column-driven writes; it does not make the entire application read-only. Bases distinguishes note, file, and formula properties, and explicit group lists can hide values omitted from the list. [Bases syntax](https://obsidian.md/help/bases/syntax). Keep `bob ref list` as the authority for what remains to read. Compare the browser against it before deciding that the visual overview saves time. Do not drag reference bundles between folder columns as a substitute for Bob's reference-management commands.

**Color highlights are independent of the Highlights PDF pipeline.** The new syntax is, for example, `==🔵A claim to revisit==`; six colored-circle emoji are recognized. The editor offers a color menu and an inline swatch. [Formatting documentation](https://obsidian.md/help/syntax). A good trial would use only two colors in your own synthesis or article drafts—perhaps one for a question, one for a candidate conclusion—before inventing a larger taxonomy. Those meanings would be your convention, not Bob semantics.

Your generated PDF annotations currently use quote/note callouts. Inserting native colors inside `<!-- highlights:begin -->` and `<!-- highlights:end -->` risks losing the edits on the next scan, as the local importer contract explicitly warns. Put authored colored observations outside that region. Native highlights do not automatically import PDF colors, update reading status, create tasks, or become visible to Bob's review system. I did not validate their appearance through your article/PDF export pipeline; test a small export before depending on color there.

A few upgrade details are more important than their placement in the release notes suggests:

- **Callout styling deserves one visual check.** The 1.13 CSS contract changes `--callout-color` from an RGB triplet to a valid CSS color. An old custom declaration may need a value such as `rgb(82, 154, 221)`. Since reference imports are callout-heavy, open a representative note in both reading view and Live Preview. I did not inspect installed snippets and am not reporting a confirmed break. [1.13 developer notes](https://obsidian.md/changelog/2026-07-30-desktop-v1.13.4/).
- **Use native image viewing before editing generated embeds.** The full-screen viewer, image navigation, and keyboard/Vim sizing arrived during 1.13. The viewer is useful for imported image annotations without altering their source text. Size edits inside generated regions have the same overwrite limitation as color edits. [Image changes in 1.13.2](https://obsidian.md/changelog/2026-07-14-desktop-v1.13.2/).
- **Several improvements require no adoption project.** The release fixes periodic large-vault input lag, list-marker duplication on paste, and Mac paragraph-selection problems. The later 1.14.1 fix for Vim numbered-list deletion/pasting is relevant to your keyboard-heavy editing. Observe these in normal work; do not infer that every residual delay originates in core Obsidian. [Public 1.14 fixes](https://obsidian.md/changelog/2026-10-05-desktop-v1.14.4/), [1.14.1](https://obsidian.md/changelog/2026-09-08-desktop-v1.14.1/).
- **Do not plan around superseded intermediate behavior.** The URI-action confirmation added in early 1.13 was removed in 1.13.6. The temporary 1.14.0 switch to Temml was replaced by MathJax 4.1.3 in 1.14.1. Both corrections matter when reading older upgrade advice. [1.13.6](https://obsidian.md/changelog/2026-08-10-desktop-v1.13.6/), [1.14.1](https://obsidian.md/changelog/2026-09-08-desktop-v1.14.1/).

I would spend the first short session checking the installer, opening one external research document, using the new settings search, and viewing a reference image. Only then try colored prose or a disposable Bases view. No migration is necessary to collect most of the benefit.

The following ranking combines likely frequency of use, fit with your current system, and effort to adopt. Confidence describes that fit, not a live compatibility test. The last two entries are explicitly conditional.

1. **External Markdown files plus Finder Quick Look — 1.14; adopt first.** High confidence, low effort after the installer prerequisite. Open a SASE report or repository README directly in Obsidian; preview another in Finder with Space. This gives your research/code documents a better reading surface while preserving their existing location and ownership. Keep your current default editor until you have tried the workflow. [How to use it](https://obsidian.md/help/manage-notes).

2. **Improved quick-switcher, link-suggestion, and sidebar search — 1.14; use immediately.** High confidence, almost no setup. Try familiar reference and project names, plus an archive exclusion in File Explorer. This helps the repeated navigation around your existing task and reading workflows. There is no reason to redesign the review walk to benefit. [Search improvements](https://obsidian.md/changelog/2026-09-29-desktop-v1.14.3/).

3. **Searchable settings with keyboard/Vim navigation — 1.13; make it the default way to find settings.** High confidence. Search by setting name or description; use arrows/Enter and Cmd-F to return to search. A separate settings window is optional. Community-plugin search depends on adoption of the new settings API. [Settings changes](https://obsidian.md/changelog/2026-07-30-desktop-v1.13.4/). Your current Bob Articles tab still implements imperative `display()`, so I would not expect its individual settings to become searchable automatically. Migrating that small tab is a plausible later maintenance improvement, not a prerequisite to using the upgrade. [Plugin migration contract](https://docs.obsidian.md/plugins/guides/migrate-declarative-settings).

4. **Full-screen image viewing and keyboard/Vim image controls — 1.13; try on reference figures.** High confidence for viewing, moderate for frequent editing. Navigate images from an image-heavy reference note. For your own embeds, try `+`/`-`, `0`, or `:image grow`, `:image shrink`, and `:image reset` with an image selected. Keep generated reference embeds unchanged when persistence matters. [Image controls](https://obsidian.md/changelog/2026-07-14-desktop-v1.13.2/).

5. **Per-device text size and font-size commands — 1.14; set once on the MacBook.** High confidence, low effort. The font size moved out of `appearance.json` into device-local storage, and increase/decrease commands are available. [Storage change](https://obsidian.md/changelog/2026-09-15-desktop-v1.14.2/), [commands](https://obsidian.md/changelog/2026-09-29-desktop-v1.14.3/). My inference is that sharing the vault configuration through Git no longer carries this setting to another device either. Pick a comfortable laptop size, and bind commands only if you often change it while reading. This applies to note text size, not every aspect of interface zoom.

6. **Native colored highlights — 1.14; adopt lightly in authored prose.** Moderate-to-high confidence, very low effort. Try `==🟣Question to investigate==` in a synthesis note outside imported regions. Keep the words meaningful without color, and avoid using highlights as another task/status system. Check one export before making them part of a publishing convention. [Color syntax](https://obsidian.md/help/syntax).

7. **Bases Kanban and group controls — 1.14; run a small reference-browsing experiment.** Moderate confidence, moderate effort. Use kind/parent to browse a collection, and consider formula grouping to prevent card-driven property changes. Start with every group visible. Promote the experiment only if it answers a recurring question faster than `bob ref list` or existing navigation. A task-lane board or editable reading-status board has substantially higher integration cost. [Kanban behavior](https://obsidian.md/help/bases/views/kanban).

8. **Faster standalone Obsidian CLI — 1.12.7; verify only if the old installer missed it.** High relevance to your tooling, uncertain novelty. Bob already has a live query engine that delegates to `obsidian eval`, while native Bob queries do not need the desktop app. The new CLI executable can improve the former path. [1.12.7 change](https://obsidian.md/changelog/2026-03-23-desktop-v1.12.7/). If needed, register it from Settings → General → Command line interface and use read-only inspection first. The CLI requires the app and can launch it; it is not a headless replacement for Bob. Generic native task writes should not replace Bob gestures that coordinate dependencies, freshness, and ledger state. [CLI setup and behavior](https://obsidian.md/help/cli).

9. **iOS Quick Capture and configurable Share Sheet destinations — conditional mobile follow-up.** Low confidence without knowing your phone workflow. The new 1.14 Quick Capture requires iOS 26 and can capture without loading the vault; 1.13 improved Share Sheet destinations/templates. [iOS documentation](https://obsidian.md/help/ios). This is not provided by upgrading the Mac alone and does not replace Bob Mac Capture's grammar. Consider one plain inbox destination only if phone capture is currently painful and the route into your Git-synced Bob vault is established. It should compete on convenience with your existing Keep intake, not introduce another unreviewed inbox or a second sync engine.
