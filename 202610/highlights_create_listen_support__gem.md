# Research & Architectural Design: `--listen` Support and Target Expansion in `bob highlights create`

**Author:** Researcher gem (`research.3r.gem`)  
**Date:** 2026-10-06  
**Status:** Complete  
**Scope:** `bob-cli` (`bob highlights create`), `sase-listen`, `chezmoi` (`~/.config/bob/config.yml`), and Bob Obsidian Vault Sync  

---

## 1. Executive Summary

This research investigates adding a new `--listen` option to the `bob highlights create` command alongside expanding the positional target argument to support direct PDF files, PDF URLs, and arXiv paper URLs. The primary motivation is to **close the loop between mobile audio consumption and durable personal knowledge management**: allowing Bryan to listen to AI-narrated articles and academic papers on his phone via AntennaPod, while automatically tracking the source documents, companion audio, and reading lifecycle within his Bob Obsidian reference note system (`ref/` notes, `lib/` archives, and GTD `^ref` review tasks).

### Key Findings & High-Level Recommendations

1. **Strong Conceptual Value:** The proposed workflow eliminates an acute "orphaned listening" problem where podcasts generated by `sase-listen` lack durable integration with the reading queue, task scheduler, and Highlights annotation pipeline. Unifying these systems is a high-leverage GTD improvement.
2. **Command Semantic Tension & The "Web Gap":** 
   - Historically, `bob highlights create` was strictly scoped to compiling local Markdown files to PDF via Pandoc, while `bob highlights clip` was created to capture web URLs into reader PDFs.
   - If `create` is expanded to accept arbitrary URLs and PDFs, it shifts from a "Markdown compiler" into a general document intake command.
   - Crucially, `sase-listen render`'s most frequent use case is web articles. If `--listen` is only implemented on `create` and `create` only handles PDFs/Markdown, Bryan would be unable to listen to web articles via Bob.
   - **Recommended Resolution:** Implement unified target dispatch in `create` (supporting Markdown, local PDFs, PDF URLs, arXiv URLs, and delegating HTML articles to reader clipping), and build the underlying listen runner as a shared component so that `bob highlights clip` can also offer `-L, --listen`.
3. **Vault Taxonomy Alignment:** `create` currently defaults `--ref-type` to `chat`. Academic papers and arXiv preprints must not land in `xlib/chat/`; they must default to `papers` (or `blogs` for web clips).
4. **Full-Output Pass-Through:** `sase-listen render` must be spawned with inherited stdio (`stdin`, `stdout`, `stderr`). AI voice synthesis takes 20–90 seconds; capturing or buffering output produces a silent, frozen terminal that breaks user trust. Streaming Rich progress bars and live status gives necessary visual feedback.
5. **Configurability via Chezmoi:** The listen command should not be hardcoded to `sase-listen`. Instead, it should be configurable under `highlights.listen_command` in `~/.config/bob/config.yml` (managed in `chezmoi`), with an environment variable override (`BOB_HIGHLIGHTS_LISTEN_COMMAND`).
6. **Pre-computation Execution Order:** `sase-listen render` must execute *before* Bob stamps the PDF marker or copies companion files. This ensures that the generated audio file and metadata are known and can be embedded immediately into the PDF marker and LaTeX play links, preventing partial vault writes if audio synthesis fails.

## 2. Current Architecture & Existing Foundations

### 2.1 The Highlights Pipeline in `bob-cli`

Bob's reference note architecture (`src/native/highlights_ref/`) operates as a two-stage intake and synchronization pipeline:

```
[Markdown / Web / PDF]
        │
        ▼
   bob highlights create / clip
        │
        ├─► Converts / Downloads PDF
        ├─► Injects Page-1 Marker (/Text Annotation)
        ├─► Discovers & Copies Companion Audio (.mp3)
        │
        ▼
   ~/bob/xlib/<ref_type>/<name>.pdf  (+ .mp3)   [Intake Queue]
        │
        ▼
   bob highlights scan (or bob_xlib_pull cron)
        │
        ├─► Moves to ~/bob/lib/<ref_type>/<name>.pdf (+ .mp3)
        ├─► Generates / Updates ~/bob/ref/<ref_type>/<name>.md
        │     - Frontmatter: type: "[[ref]]", audio: "[[lib/...]]", status: ready
        │     - Lifecycle Task: - [ ] ^ref
        │     - Audio Embed: ![[lib/<ref_type>/<name>.mp3]]
        │     - Managed Highlights Region: <!-- highlights:begin --> ... <!-- highlights:end -->
        │
        ▼
   Obsidian Vault & GTD Review Walk
```

#### Existing Audio & Listen Card Support (Commit `2152202`)
Recent work (`listen_card_create_audio.md`) laid significant groundwork for audio integration:
- `audio.rs`: Defines `audio_library_root()` which searches `BOB_HIGHLIGHTS_AUDIO_LIBRARY`, `highlights.audio_library` config, and `$XDG_DATA_HOME/sase-listen/library` (`~/.local/share/sase-listen/library`).
- Companion Audio Resolution: Discovers audio via `--audio <path>`, frontmatter `audio.episode_id`, or by scanning `manifest.json` files in the library for matching source or script sha256 digests (`find_audio_by_script_hash`).
- Audio Stamping & Copying: `create.rs` sets up an `AudioCopyPlan`, copies the `.mp3` beside the PDF in `xlib/`, stamps `audio: [[lib/...]]` in the marker, and injects a clickable Play button (`obsidian://open?vault={vault}&file={path}`) via the Pandoc LaTeX preamble.
- Vault Note Embed: During `scan`, `maybe_insert_audio_embed` automatically adds `audio: "[[...]]"` frontmatter and inserts `![[...]]` into the markdown body.

### 2.2 `sase-listen` Pipeline & Output Behavior

`sase-listen` (`gh:sase-org/sase-listen`) converts articles and papers into chaptered MP3 episodes and publishes them to podcast feeds:
- **CLI Command:** `sase-listen render <source> -e <edition>` (default edition is `brief`; user requested `-e full`).
- **Supported Sources:**
  - Local Markdown files (`.md`)
  - Local PDF documents (`.pdf`)
  - Remote HTTP/HTTPS URLs (HTML web articles, direct PDFs)
  - arXiv URLs (special extraction via `web/arxiv.py`)
- **arXiv Handling:**
  - `arxiv_paper_id(url)` matches `arxiv.org`, `www.arxiv.org`, `export.arxiv.org` paths `/abs/<id>`, `/html/<id>`, `/pdf/<id>`.
  - Automatically resolves to canonical PDF: `https://arxiv.org/pdf/<paper_id>`.
  - Extracts text directly from PDF bytes using `pdfminer.six`.
- **Storage & Publishing:**
  - Stores output in `~/.local/share/sase-listen/library/<episode-id>/`.
  - Contains `<slug>.mp3`, `manifest.json`, and `narration.md`.
  - Automatically publishes to the podcast feed (local or remote via SSH host streaming) unless `--no-publish` is given.
  - Manifest records `episode_id`, `created_at`, `audio: {"file": "<slug>.mp3"}`, and `source: {"url": "...", "sha256": "..."}`.
- **Rich Terminal Output:**
  - Uses `rich` live display: multi-stage progress (fetch, extract, script, chunk synthesis, gate verification, audio mastering, ID3 tags, and publish upload).
  - Emits cost estimates, chapter timelines, word counts, and podcast feed notices.

## 3. Critical Evaluation & Plan Critique

### 3.1 Is this a good idea?

**Yes, strongly endorsed.**
1. **Unifies Two Disconnected Loops:** Currently, Bryan has two separate intake workflows: reading/highlighting via `bob highlights` and audio listening via `sase-listen`. Without this integration, listening to an episode on AntennaPod is an ephemeral experience—no task is created in Obsidian, no reference note tracks the paper, and no PDF is staged for highlights when sitting down at a computer.
2. **True "Single-Gesture"GTD Capture:** By tying `--listen` to `bob highlights create`, a single terminal invocation publishes the audio to AntennaPod on the phone and queues the paper in `xlib` so the morning GTD review walk automatically surfaces it.

### 3.2 Architectural Critique & Tensions

While the goal is sound, the specific proposal has three major architectural friction points that require thoughtful resolution:

#### Critique 1: Semantic Overloading of `bob highlights create`
- `bob highlights create` was explicitly named and documented as *"Render Markdown as a Highlights-ready PDF"*.
- When `<target>` is already a PDF (e.g. `paper.pdf` or an arXiv paper), Bob is **not creating** a PDF. It is *importing* and *stamping* an existing document.
- The user prompt acknowledges this awkwardness: *"When `<target>` points to a PDF, we obviously don't need to create a new PDF (just use that one)..."*
- If `create` accepts URLs, local PDFs, arXiv preprints, and Markdown files, it transforms into a general `intake` or `import` command.

#### Critique 2: The Web Article Gap & Overlap with `bob highlights clip`
- Bob already has a specialized URL capture command: `bob highlights clip <URL>` (documented in `docs/highlights-clip.md`), which uses Playwright + Defuddle to turn web pages into reader-mode PDFs.
- `sase-listen`'s primary capability is rendering web articles (e.g., Substack, blog posts, news).
- If `--listen` is added *only* to `bob highlights create`, and `create` is restricted to Markdown and PDFs:
  - How does Bryan listen to a web article?
  - If he runs `bob highlights clip <URL>`, there would be no `--listen` flag.
  - If he runs `bob highlights create <URL>`, what happens if the URL is an HTML article instead of a PDF?
- **Conclusion:** Either `create` must handle HTML articles (duplicating `clip`), or `create` delegates HTML articles to `clip`, or both `create` and `clip` must support `--listen`.

#### Critique 3: Vault Taxonomy & Default `ref_type`
- `create` currently defaults `--ref-type` to `chat` (`const DEFAULT_REF_TYPE: &str = "chat"`).
- `clip` defaults `--ref-type` to `blogs`.
- In Bryan's vault (`~/bob/ref/` and `~/bob/lib/`), there are four primary reference subdirectories:
  - `papers/` (academic research, arXiv preprints)
  - `blogs/` (articles clipped from the web)
  - `chat/` (AI conversation logs and transcripts)
  - `docs/` (software documentation)
- If a user runs `bob highlights create https://arxiv.org/abs/2608.25174 --listen` and Bob uses `create`'s default `ref_type`, the paper lands in `~/bob/lib/chat/` and `~/bob/ref/chat/`. This corrupts Bryan's vault organization!
- **Adjustment Required:** Bob must dynamically assign `ref_type` based on target detection (arXiv & academic PDFs -> `papers`; web articles -> `blogs`; markdown -> `chat`), while still allowing `--ref-type` to explicitly override.

#### Critique 4: Dry-Run and Cost Visibility
- Voice synthesis via `sase-listen` costs real API dollars (Gemini TTS / OpenAI) and takes compute.
- `bob highlights create --dry-run` must coordinate with `sase-listen --dry-run`.
- When `-d, --dry-run` is passed, Bob should run `sase-listen render <target> -e full --dry-run`, allowing Bryan to inspect the chapter map, word count, narrator, and estimated cost without synthesizing audio chunks or charging API credits.

## 4. Design & Recommended Solution

### 4.1 Proposed Target Grammar & Smart Dispatch

Rather than forcing the user to remember whether a source is a "clip" or a "create", `bob highlights create` should act as an intelligent document intake front-door.

The positional argument is renamed in help/documentation from `MD_FILE` to `TARGET` (while maintaining backwards compatibility for existing scripts). Target classification proceeds as follows:

```
                          ┌───────────────────────┐
                          │ bob highlights create │
                          │       <TARGET>        │
                          └──────────┬────────────┘
                                     │
                 ┌───────────────────┴───────────────────┐
                 ▼                                       ▼
        [Local Filesystem]                               [URL / Remote]
                 │                                       │
         ┌───────┴───────┐                       ┌───────┴───────────────┐
         ▼               ▼                       ▼                       ▼
    [*.md file]     [*.pdf file]          [arXiv Identifier / URL]  [Direct PDF URL]
         │               │                       │                       │
    Pandoc LaTeX    Skip Pandoc;            Canonicalize to         HTTP Download
    Compilation     Load & Validate         https://arxiv.org/pdf/  to temp PDF
         │               │                       │                       │
  Default ref_type: Default ref_type:      Default ref_type:       Default ref_type:
      "chat"          "papers"                 "papers"                "papers"
         │               │                       │                       │
         └───────────────┴───────────┬───────────┴───────────────────────┘
                                     │
                     ┌───────────────┴───────────────┐
                     │ If -L, --listen is enabled:   │
                     │  1. Run listen_command        │
                     │  2. Inherit stdio (stream UI) │
                     │  3. Discover output episode   │
                     │  4. Bind audio & Play link    │
                     └───────────────┬───────────────┘
                                     │
                                     ▼
                     Stamp Page-1 PDF Marker & Info
                     Copy PDF + Companion MP3 to xlib/
                                     │
                                     ▼
                     next: bob highlights scan
```

#### Classification Rules:
1. **Local Markdown:** Path exists and has extension `.md`, `.markdown`, or `.txt`.
   - Behavior: Pandoc compile -> stamp marker -> copy to `xlib/chat/`.
2. **Local PDF:** Path exists and has extension `.pdf`.
   - Behavior: Validate PDF header (`%PDF-`) -> stamp marker -> copy to `xlib/papers/`.
3. **arXiv Target:** Matches arXiv URL or `arxiv:<id>` syntax:
   - Hosts: `arxiv.org`, `www.arxiv.org`, `export.arxiv.org`.
   - Paths: `/abs/<id>`, `/pdf/<id>`, `/html/<id>`.
   - Resolution: Rewrite to canonical PDF URL: `https://arxiv.org/pdf/<id>`.
   - Behavior: Download PDF -> stamp marker with `source_url: https://arxiv.org/abs/<id>` -> install to `xlib/papers/<id>.pdf`.
4. **Direct PDF URL:** Remote `http(s)://` URL ending in `.pdf` or returning `Content-Type: application/pdf`.
   - Behavior: Download PDF -> stamp marker with `source_url` -> install to `xlib/papers/<stem>.pdf`.
5. **HTML Web Article URL (Delegation Escape Hatch):**
   - If a user passes `https://example.com/article` (non-PDF, non-arXiv) to `create`:
   - *Option 5A (Strict):* Exit 1 with error: `target is a web article; use 'bob highlights clip <URL>'`.
   - *Option 5B (Graceful Delegation - Recommended):* Automatically invoke the web-clip adapter pipeline (Playwright reader mode) to render the PDF into `xlib/blogs/`. If `--listen` was supplied, execute the listen pipeline for that URL.

### 4.2 Configuration Schema in Chezmoi (`config.yml`)

The integration must avoid hardcoded assumptions about the `sase-listen` binary. It is configured in Bryan's `chezmoi` repository under `home/dot_config/bob/config.yml`.

#### Proposed YAML Configuration:
```yaml
# In ~/.config/bob/config.yml (chezmoi: home/dot_config/bob/config.yml)
highlights:
  # Existing pre-scan hook
  pre_scan_hook: PATH="$HOME/bin:$PATH" bob_xlib_pull

  # Command template executed when --listen is passed to highlights create / clip.
  # Placeholders:
  #   {target}   - The raw target argument (shell-quoted)
  #   {edition}  - Selected edition (default: full)
  listen_command: sase-listen render {target} -e full

  # Optional companion audio library root (defaults to ~/.local/share/sase-listen/library)
  # audio_library: ~/.local/share/sase-listen/library

  # Optional URI template used for the Play button in generated PDFs
  # audio_link_template: "obsidian://open?vault={vault}&file={path}"
```

#### Precedence & Environment Variables:
1. `BOB_HIGHLIGHTS_LISTEN_COMMAND` environment variable.
2. `highlights.listen_command` in `~/.config/bob/config.yml`.
3. If neither is configured and `-L, --listen` is used:
   - Fail fast with exit code 1:
     ```
     bob highlights: error: --listen requires highlights.listen_command in ~/.config/bob/config.yml or BOB_HIGHLIGHTS_LISTEN_COMMAND
     hint: add 'listen_command: sase-listen render {target} -e full' under highlights: in your Bob config
     ```

### 4.3 CLI Option Contract (`cli_rules.md` Compliance)

Following the project's strict CLI guidelines in `sase/memory/cli_rules.md`:
- **Long Option:** `--listen`
- **Short Alias:** `-L` (Note: `-l` is already claimed by `-l, --lib-dir PATH` on `create`).
- **Mutual Exclusions:** `--listen` conflicts with `-n, --no-audio` (which disables companion audio).
- **Position in Help:** Listed alphabetically in `--help` output.
- **Dry-run Integration:** When combined with `-d, --dry-run`, Bob executes the listen command with `--dry-run` (or prints the would-run command) so no audio synthesis is billed.

```bash
bob highlights create [OPTIONS] <TARGET>

Arguments:
  <TARGET>  Markdown file, PDF document, PDF URL, or arXiv URL/identifier

Options:
  -a, --audio <PATH>       Use this companion audio file instead of discovering one
  -b, --bob-dir <PATH>     Bob vault root [default: BOB_DIR or ~/bob]
  -d, --dry-run            Plan all writes and audio render without modifying disk
  -f, --force              Overwrite an existing target intake PDF
  -i, --include-id         Embed the filename stem as the marker id
  -L, --listen             Generate podcast episode via the configured listen command
  -l, --lib-dir <PATH>     Archived library directory [default: <bob-dir>/lib]
  -n, --no-audio           Skip companion audio discovery and copy
  -o, --output <PDF>       Complete destination path including .pdf filename
  -P, --parent <NOTE>      Obsidian note target for the marker parent [default: obsidian_ref]
  -r, --ref-dir <PATH>     Reference note directory [default: <bob-dir>/ref]
  -s, --status <STATUS>    Lifecycle status [default: ready]
  -t, --ref-type <DIR>     Library subdirectory (chat, papers, blogs) [default: auto]
  -x, --xlib-dir <PATH>    Intake directory [default: <bob-dir>/xlib]
```

### 4.4 The Full Execution Lifecycle

Here is the exact end-to-end execution sequence when `bob highlights create https://arxiv.org/abs/2608.25174 --listen` is executed:

#### Step 1: Preflight & Target Analysis
1. Parse and sanitize `<target>`.
2. Recognize arXiv URL: extract paper ID `2608.25174`.
3. Resolve canonical download URL: `https://arxiv.org/pdf/2608.25174`.
4. Determine target stem: `2608_25174` (or arXiv slug) and destination path: `~/bob/xlib/papers/2608_25174.pdf`.
5. Check collision: ensure `xlib/papers/2608_25174.pdf` and `lib/papers/2608_25174.pdf` do not already exist (refuse unless `--force` for intake).

#### Step 2: Running the Listen Command (Streamed Output)
1. Read `listen_command` from config: `sase-listen render {target} -e full`.
2. Expand placeholder: replace `{target}` with `https://arxiv.org/abs/2608.25174`.
3. Spawn child process via `sh -c`:
   ```rust
   let status = std::process::Command::new("sh")
       .arg("-c")
       .arg(&command_str)
       .stdin(std::process::Stdio::inherit())
       .stdout(std::process::Stdio::inherit())
       .stderr(std::process::Stdio::inherit())
       .status()
       .map_err(|e| CommandError::new(format!("failed to execute listen command: {e}")))?;
   ```
4. Full live progress from `sase-listen` (Rich rendering, chunk counters, narration, AntennaPod RSS publishing) streams directly to Bryan's terminal.
5. If the child process exits with non-zero status:
   - Immediately abort with error: `bob highlights: error: listen command failed (exit code {code})`.
   - Write nothing to `xlib/`.

#### Step 3: Discovering the Audio Episode
1. Inspect `sase-listen`'s library directory: `~/.local/share/sase-listen/library/`.
2. Locate the episode created by the run. Because `sase-listen`'s `manifest.json` stores `source: {"url": "https://arxiv.org/abs/2608.25174"}`, match against `manifest.json`.
3. Extract audio filename (e.g., `symphony_codex-4a2f8b.mp3`).
4. Set up `AudioCopyPlan`:
   - Source: `~/.local/share/sase-listen/library/<episode-id>/<file>.mp3`
   - Destination: `~/bob/xlib/papers/2608_25174.mp3`
   - Vault reference: `lib/papers/2608_25174.mp3`

#### Step 4: Acquiring the PDF Document
- **If target was a local PDF:** Use existing file bytes directly.
- **If target was arXiv / remote PDF:**
  - Check if `sase-listen` already cached the pristine source PDF in `~/.local/share/sase-listen/sources/<slug>/source.pdf`.
  - If cached by `sase-listen`, copy directly from source cache.
  - If not cached (or `--listen` was omitted), download the PDF bytes via HTTP client.

#### Step 5: Stamping Marker & Installing to Intake
1. Compose page-1 marker:
   ```json
   {
     "status": "ready",
     "parent": "obsidian_ref",
     "title": "An open-source spec for Codex orchestration: Symphony",
     "id": "2608_25174",
     "source_url": "https://arxiv.org/abs/2608.25174",
     "captured": "2026-10-06",
     "audio": "[[lib/papers/2608_25174.mp3]]"
   }
   ```
2. Stamp marker onto the PDF using `lopdf` (`stamp_and_install`).
3. Atomically copy the MP3 to `~/bob/xlib/papers/2608_25174.mp3`.
4. Install the stamped PDF to `~/bob/xlib/papers/2608_25174.pdf`.

#### Step 6: Console Output & Next Steps
Print beautiful, colored confirmation matching Bob CLI styling:
```
✓ created Highlights-ready PDF
pdf: /home/bryan/bob/xlib/papers/2608_25174.pdf
audio: /home/bryan/bob/xlib/papers/2608_25174.mp3 (from sase-listen library)
audio_link: obsidian://open?vault=bob&file=lib/papers/2608_25174.mp3
title: An open-source spec for Codex orchestration: Symphony
status: ready
parent: obsidian_ref
id: 2608_25174
pages: 18
next: bob highlights scan
```

#### Step 7: Downstream Vault Synchronization (`bob highlights scan`)
When `bob highlights scan` runs (or is invoked automatically by `bob_xlib_pull` on Bryan's Mac):
1. Intake moves `xlib/papers/2608_25174.pdf` -> `lib/papers/2608_25174.pdf`.
2. Intake moves `xlib/papers/2608_25174.mp3` -> `lib/papers/2608_25174.mp3`.
3. Note sync writes `ref/papers/2608_25174.md`:
   ```markdown
   ---
   type: "[[ref]]"
   ref_type: papers
   title: "An open-source spec for Codex orchestration: Symphony"
   id: 2608_25174
   source_url: https://arxiv.org/abs/2608.25174
   audio: "[[lib/papers/2608_25174.mp3]]"
   created: 2026-10-06T14:30:00-04:00
   status: ready
   ---

   - [ ] [[2608_25174.pdf]] An open-source spec for Codex orchestration: Symphony ^ref

   ![[lib/papers/2608_25174.mp3]]

   ## Highlights

   <!-- highlights:begin -->
   <!-- highlights:end -->
   ```
4. **Outcome:**
   - Bryan's phone (AntennaPod) has the episode downloaded and queued for audio listening.
   - Bryan's Obsidian vault has the paper tracked in GTD under `^ref`.
   - The ref note embeds the native audio player.
   - When Bryan annotates the PDF on iPad / Mac Highlights app, the highlights will automatically sync into the `## Highlights` section on the next scan!

## 5. Summary of Recommended Adjustments

| Aspect | User's Initial Prompt | Recommended Adjustment | Rationale |
| :--- | :--- | :--- | :--- |
| **Short Option Alias** | None specified (or `-l`) | **`-L, --listen`** | `-l` is already assigned to `-l, --lib-dir` in `create`. `-L` preserves the mnemonic while avoiding a breaking collision. |
| **Target Scope & Taxonomy** | `create <target>` for PDFs & arXiv | **Dynamic taxonomy defaults** | Local Markdown defaults to `chat`; arXiv & direct PDFs default to `papers`; web articles default to `blogs`. Avoids dumping research papers into `chat/`. |
| **Web Article Handling** | Unspecified for `create` | **Delegation to clip / shared engine** | `sase-listen` frequently renders web articles. If Bryan runs `create` on a web article, Bob should delegate to reader mode instead of failing. Furthermore, `bob highlights clip` should also gain `-L, --listen`. |
| **Execution Timing** | Unspecified | **Listen command runs FIRST** | Running audio generation before PDF stamping guarantees that audio metadata is available to embed into the marker and Play buttons, and prevents corrupted/partial vault state if synthesis fails. |
| **Output Streaming** | Output shown in full | **Inherit stdio (`Stdio::inherit`)** | Confirmed: piping/buffering output would freeze the UI for 1–2 minutes during TTS. Directly inheriting stdout/stderr preserves Rich live progress bars. |
| **Dry-Run Coordination** | Unspecified | **Forward `--dry-run` to listen** | Voice synthesis costs API money. `--dry-run` on Bob must run `sase-listen --dry-run` to display word count and cost estimates without paying for synthesis. |
| **PDF Source Reuse** | Download PDF independently | **Reuse `sase-listen` acquired source** | `sase-listen` already downloads and caches the source PDF under `~/.local/share/sase-listen/sources/`. Reusing this cache avoids duplicate network requests to arXiv. |

## 6. Implementation Blueprint

### 6.1 Changes to `chezmoi` (`home/dot_config/bob/config.yml`)
Add `listen_command` under `highlights:`:
```yaml
highlights:
  pre_scan_hook: PATH="$HOME/bin:$PATH" bob_xlib_pull
  listen_command: sase-listen render {target} -e full
```

### 6.2 Changes to `bob-cli` Rust Codebase

1. **`src/native/config/mod.rs`:**
   - Add `listen_command: Option<String>` to `RawHighlights` and `HighlightsConfig`.
   - Expose `listen_command(&self) -> Option<&str>`.
   - Parse and validate the command string.
2. **`src/native/highlights_ref/cli.rs` & `create.rs`:**
   - Update Clap definition in `create.rs`:
     - Rename positional `md-file` -> `target` (value name `TARGET`, description: *"Markdown file, PDF file, PDF URL, or arXiv URL to intake"*).
     - Add `Arg::new("listen").long("listen").short('L').action(ArgAction::SetTrue).conflicts_with("no-audio")`.
3. **`src/native/highlights_ref/target.rs` (New Module):**
   - Implement `TargetKind`: `Markdown(PathBuf)`, `LocalPdf(PathBuf)`, `Arxiv(String, String)` (ID & PDF URL), `RemotePdf(String)`, `WebArticle(String)`.
   - Implement `arxiv_paper_id(url)` and `arxiv_pdf_url(url)` (porting pure logic from `sase-listen/web/arxiv.py`).
   - Implement target classification and smart `ref_type` defaults.
4. **`src/native/highlights_ref/listen.rs` (New Module):**
   - Implement `execute_listen_command(config, target, dry_run)`:
     - Formats command string using `{target}` placeholder.
     - Appends `--dry-run` if `dry_run` is active.
     - Spawns subprocess with `Stdio::inherit()`.
   - Implement `find_rendered_episode(library, target)`:
     - Inspects newest `manifest.json` entries in `audio_library_root()`.
     - Matches `manifest.source.url` or `source.path` against target.
     - Returns path to generated `.mp3` and episode ID.
5. **`src/native/highlights_ref/create.rs` (Workflow Integration):**
