# Comparison

Intro paragraph before the table so the page has ordinary prose to compare against when selecting.

| | **#now** | **In Progress** |
|---|---|---|
| **Kind** | A tag in the task text. It is independent of the checkbox, so it can sit on any open status. | A checkbox status: the top rung of the ladder. |
| **Question it answers** | "What have I bet on this week?" | "What have I actually been working on?" |
| **Set by** | **You.** Type it, or capture it from the menu bar. Phase 1 adds a toggle command. | **The tools.** An =x close turns a worked-on link into in progress and gives it a tomato. The hooks then push it down transcluded dependencies. |
| **Cleared by** | **Only you**, at the Monday review. Untag anything with no tomato in seven days that is not one of the week's bets. | **The status hooks, automatically** every fifteen minutes. An area or project resets once neither today's ledger nor the previous daily links it. |

# Decisions

| Decision | Resolution and reason |
|---|---|
| Used or remaining? | Both researchers favor remaining. Store vendor used percent; consistently display N percent left. |
| Primary or most constrained window? | Use the most constrained applicable window; retain its scope. Neither vendor position nor a model-specific minimum describes the entire provider. |
| Pace gauge as the foundation? | Keep the question about lasting until reset; decline the single-snapshot forecast and multi-segment meter as defaults. They add assumptions and decoding work. |
| Main TUI location? | Evolve Provider Routing into one Providers home. Add a read-only Usage view; keep routing changes in an explicitly selected Routing view. |
