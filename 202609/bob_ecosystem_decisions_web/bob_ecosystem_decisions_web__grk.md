# A Decisions Memory Web for the Bob Tool Stack

**Researcher:** `grk` (independent swarm member)
**Date:** 2026-09-29
**Question:** How should Bryan implement a SASE memory web, heavily inspired by
the `sase` project's `decisions` web, that records the important architectural
and policy choices for `bob-cli`, `bob-plugins`, `bob-mac-capture`, and the
Obsidian vault?

**Recommendation in one line:** Add a project-scoped `decisions` web under
`bob-cli`'s `sase/memory/`, copy the sase record contract (immutable Claim / Why
/ Cost / Reopens when), seed eight boundary strands that already exist as
scattered prose, and keep vault-operating policy in home `obsidian.md` rather
than trying to make one web serve every SASE project that touches `~/bob`.

---

## 1. Verdict

This is a good idea. I would implement it. I would not implement it as stated.

The sase `decisions` web is the right *mechanism*. The stated *scope* — one web
that equally covers bob-cli, bob-plugins, bob-mac-capture, *and* "the Obsidian
vault in general" — mixes two audiences and two lifetimes of knowledge. That
mix is the main failure mode.

Sase's own doctrine already answers the "is this premature machinery?"
objection. The `corpus-before-mechanism` decision forbids retrieval engines
ahead of a corpus; it does **not** forbid naming a corpus that already exists.
Bob already has that corpus. It is just unaddressable: linked-repo blurbs in
`sase/sase.yml`, home `~/sase/memory/obsidian.md`, `docs/vault-git-sync.md`,
`docs/task-status-hooks.md`, the plugins README development model, and the Mac
capture README runtime contract. A `decisions` web is the mechanism that corpus
has earned.

What I would change, and I want these called out as requirement adjustments:

1. **Place the web in bob-cli project memory, not home memory.** Home webs
   render into every project, including sase, whose `decisions` roster is
   already ~110 lines / ~1.6k tokens of always-loaded context.
2. **Do not treat "the vault in general" as a fourth product in this web.**
   Vault *operating* policy that sase agents also need already lives in home
   `obsidian.md`. Promote a vault item into the bob-cli web only when the Bob
   *tools* enforce it and agents working in this project keep violating it.
3. **Do not stand up SASE projects for bob-plugins or bob-mac-capture** just
   to host memory. They are linked repos of bob-cli. Agents that edit them
   launch from this project and already see this project's webs.
4. **Seed eight strands, not "the important decisions."** Sase shipped its
   web with six records and grew to twenty-four. The roster is paid on every
   turn. Start at the size the corpus actually supports.
5. **Keep living contracts in docs.** Capture grammar, plugin keymaps, CLI
   flags, and Highlights marker syntax are versioned behavior. A decision
   record is a choice among alternatives, not a subsystem overview. Sase's
   descriptor says this in the first sentence; copying the web without copying
   that rule will rot the roster.

## 2. What the sase `decisions` web actually is

Verified against the opened sase checkout
(`sase repo open sase`) and audited reads of
`decisions:corpus-before-mechanism`, `decisions:memory-webs`,
`decisions:memory-links-are-authored`,
`decisions:webs-render-in-their-own-section`,
`decisions:single-turn-agents`, and `decisions:rust-core-required`.

### 2.1 Shape

| Piece | Path | Always loaded? |
| --- | --- | --- |
| Descriptor | `sase/memory/decisions.md` | Yes — inlined into `## Memory Webs` |
| Strand directory | `sase/memory/decisions/<slug>.md` | No — `sase memory read decisions:<keyword>` |
| Roster | `<!-- sase:strands -->` region, regenerated by `sase memory init` | Yes, as part of the descriptor |

Descriptor frontmatter (copy this):

```yaml
---
web: true
description:
  Architectural decision records — accepted choices, their rejected alternatives, and
  what would reopen them.
roster: list
roster_label: DECISIONS
strand_noun: decision
---
```

Do not set `type:` or `parent:` on a web descriptor. Kind decides placement:
the descriptor always lands in Memory Webs, between core and reference.
`sase memory init` strips `type:`/`parent:` if present. There is no way to
make a web descriptor read-on-demand; that is the cost of
`webs-render-in-their-own-section`.

Strand frontmatter (copy this):

```yaml
---
keyword: Agents Are Single-Turn
aliases: [single turn, one-turn agent]
summary:
  A SASE agent run is one provider turn; continuation is always mechanical, never a
  promise to resume.
metadata:
  status: accepted
  decided: 2026-08-15
---
```

`roster: list` **requires** `summary`. Missing summaries fail `sase memory init`
and `sase doctor` closed.

### 2.2 Record contract

Every accepted sase strand uses the same four sections:

- **Claim.** One falsifiable sentence.
- **Why.** Why this beat the credible alternatives, with evidence (commits,
  failed experiments, observed divergence). Rejected alternatives are named,
  not implied.
- **Cost.** What you pay for keeping the claim.
- **Reopens when.** A concrete condition, not "if we change our mind."

A record is immutable once accepted. Course-change writes a *new* strand and
marks the old one with `metadata.status: superseded` or `superseded-in-part`
plus `superseded_by` and a `[[...]]` back-link in the old body. Authors do not
rewrite history. The roster keeps showing superseded entries, annotated.

That immutability is the whole point. A design doc goes stale under the code.
A decision record is a dated bet.

### 2.3 Linking and retrieval

Decisions use **authored** `[[target]]` / `![[target]]` links (the default
`link_reference: explicit`). They do **not** use glossary-style implicit
phrase matching. Do not set `closure: mentions` on this web.

Sase's `corpus-before-mechanism` record is load-bearing here: keyword-triggered
dynamic memory, episode recall, and `keywords:` metadata were each built and
then deleted. The decisions web shipped with six real records and no closure
engine. Bob should do the same: keyword addressing plus authored links, nothing
else.

### 2.4 Home / project merge (this is the trap)

`merge_memory_web_scopes` unions strands of the same web slug across home and
project. Project strands win on slug collision. The *descriptor* also comes
from the project when both exist.

Consequences:

- A home web named `decisions` would merge into sase's existing `decisions`
  web whenever a sase agent runs. Bob vault policy would appear on sase's
  roster. That is contamination, not sharing.
- A uniquely named home web (e.g. `bob-decisions`) would still inline its
  descriptor into **every** project, including sase. You would tax sase turns
  for Bob tool-stack history.
- Project-only `bob-cli` `sase/memory/decisions/` is visible to bob-cli
  agents, including those that `sase repo open` the linked plugins and
  mac-capture repos. It is invisible to sase agents, who already have home
  `obsidian.md` for vault conventions.

That last point is why "cover the vault in general" does not belong in this
web as a primary goal.

### 2.5 Token budget

Measured proxies:

| Surface | Size |
| --- | --- |
| bob-cli `AGENTS.md` today | 135 lines, ~1.8k tokens |
| sase `decisions.md` roster (24 strands) | 110 lines, 6.6k bytes, ~1.6k tokens |
| bob-cli glossary descriptor | 17 lines, ~166 tokens |

Eight list-roster items plus a one-paragraph preamble is roughly 40–60 lines,
on the order of 500–800 always-loaded tokens. That is a fair tax for a
project whose agents currently reconstruct policy from `README.md` (49k) and
`docs/capture.md` (thousands of lines). Twenty-four items on day one would
nearly double bob-cli's instruction file. Do not copy sase's *count*; copy
its *shape*.

Sase's own reopen condition on `webs-render-in-their-own-section` is "enough
memory webs that unconditionally inlining every descriptor becomes a real
token-budget problem." One web with eight strands is nowhere near that.

## 3. Critique of the plan as stated

### 3.1 What is right

- **Kind.** A memory web is the correct kind. Core notes would inline every
  body. A single reference note would become a design doc. Glossary strands
  are definitions, not bets. Decisions are bets.
- **Inspiration source.** Copying the sase descriptor preamble, list roster,
  strand template, and supersession rules is cheaper and safer than inventing
  a parallel ADR format. Agents already know `sase memory read decisions:<k>`.
- **There is a real corpus.** See §5. This is not speculative "we might want
  retrieval later."
- **Cross-repo coordination is the pain.** Capture grammar, plugin deploy, and
  vault mutation already span three git repos plus `~/bob`. Agents that edit
  the Mac app or a plugin without reading bob-cli's contract are the recurring
  failure.

### 3.2 What is wrong, or will go wrong

**Audience collision.** "Obsidian vault in general" is personal operating
policy (parent frontmatter, git sync, conflict copies, gitignored `xlib/`).
That policy must be visible when a sase agent creates a note in `~/bob`. Home
`obsidian.md` is already on `~/AGENTS.md`'s reference list for that reason.
Putting the same facts only in bob-cli `decisions` hides them from sase.
Putting them in a home `decisions` web pollutes sase. The plan as stated does
not pick.

**Living-contract capture.** If "heavily inspired" is read as "dump the
important architecture into strands," the first victims are capture grammar
and plugin keymap encyclopedias. Those pages change with versions. A
decision that restates `@route:id#pomodoro=<X>` will be wrong within a month
and still immutable. Sase's descriptor forbids this; the Bob docs corpus
tempts it constantly.

**Duplication with always-loaded one-liners.** Two of the highest-value
rules are *already* core context via `sase/sase.yml` linked-repo
descriptions:

- Do not edit custom plugins under `~/bob/.obsidian/plugins/`; edit
  `bob-plugins` and `bob plugins sync`.
- Bob Mac Capture delegates grammar, completion, preview, and vault writes
  to versioned `bob` subprocess/JSON interfaces.

A decisions web should hold the *why / alternatives / reopen*, not a second
copy of the one-liner. Keep the sase.yml blurbs; point strands at them with
`[[ ]]` only where that helps. Do not delete the blurbs in v1.

**Over-seeding.** "Think hard about which initial strands" is the right
instinct; answering it with twenty records is the wrong one. Each roster
line is a promise that an agent might `sase memory read` the body. Empty
promises train agents to ignore the web.

**No write path besides files + init.** There is no `sase memory web add`
CLI. Strands are created in the TUI Memory panel or by hand in
`sase/memory/decisions/`, then published with `sase memory init`. Plan for
that workflow; do not invent a generator.

**Plugins and mac-capture are not SASE projects.** `sase project list`
shows only `bob-cli` and `sase` as enabled user projects. Memory cannot live
"in" bob-plugins unless that repo becomes a SASE project. Do not do that
for this.

### 3.3 Alternative approaches I considered and rejected

| Approach | Why I rejected it |
| --- | --- |
| Home-scoped `decisions` web | Merges with or sits beside sase's web; taxes every project |
| Three webs (`cli`, `plugins`, `vault`) | Three always-loaded descriptors; splits a 8-item corpus |
| One fat `architecture.md` reference note | All-or-nothing read; no immutability/supersession; becomes a design doc |
| Promote plugins and mac-capture to SASE projects | Huge lifecycle cost for two linked repos that already launch from bob-cli |
| ADR files in `docs/adr/` | Invisible to agents unless also mirrored into memory; two sources of truth |
| Stuff choices into the glossary | Glossary is "what the word means"; a decision is "what we chose instead" |
| Core notes for the top five rules | Always-loaded bodies; no keyword addressing; fights the web kind |

The approach I would actually take is the recommended solution in §7.

## 4. Requirement adjustments (explicit)

These are changes to the user's stated requirements. Everything else in this
report implements the original intent.

1. **Scope the web to the Bob *tool stack* as seen from bob-cli**, i.e. this
   repo plus its linked `bob-plugins` and `bob-mac-capture` repos, plus the
   vault invariants those tools enforce. Drop "Obsidian vault in general" as
   a co-equal target.
2. **Keep home `~/sase/memory/obsidian.md` as the vault operating note**
   visible to every project. Optionally add one sentence there pointing
   bob-cli agents at `decisions:` for tool-stack bets; do not migrate the
   note into the web in v1.
3. **Name the web `decisions`**, matching sase. Agents already know the
   selector. Do not name it `bob-decisions` unless it lives in home (it
   should not).
4. **Initial corpus size is eight accepted strands** (§5.1). A ninth is
   added only when an agent or human has violated the choice, or a proposed
   change would silently reopen it.
5. **A strand must name rejected alternatives and a reopen condition.** If
   you cannot write those two sections, it is a doc, a gotcha, or a glossary
   term, and it stays where it is.
6. **Do not restate command contracts.** Link `docs/*.md` from Why/Cost
   when the living behavior is the evidence; do not paste grammar tables
   into strands.

## 5. Initial strands

Litmus test used below, copied from sase practice:

- There was a real alternative that was tried or seriously considered.
- Agents (or future-you) can violate it by local cleverness.
- The choice spans more than one file, often more than one repo.
- The body will still be true if a nearby command grows a flag.

### 5.1 Seed these eight

Each row is a strand I would author in v1. Summaries are roster-length; the
sketches under the table are the Claim / rejected alternatives / reopen
condition, not finished bodies.

| # | Keyword | Slug | Surfaces | Why it earns a strand |
| --- | --- | --- | --- | --- |
| 1 | Capture Grammar Lives In bob-cli | `capture-grammar-in-bob-cli` | cli, mac-capture, plugins that call capture | Highest cross-repo footgun |
| 2 | Plugins Repo Is The Source Of Truth | `plugins-repo-is-source` | plugins, vault, cli deploy | Already in sase.yml; still violated |
| 3 | Custom Plugins Stay Plain CommonJS | `plugins-plain-commonjs` | plugins | Explicit anti-bundler bet |
| 4 | Git Is The Only Vault Sync Engine | `git-only-vault-sync` | vault, cli, home obsidian.md | Researched and cut over; easy to reopen badly |
| 5 | Remote Wins; Local Is Quarantined | `remote-wins-conflicts` | vault-sync | The whole git-sync project's load-bearing choice |
| 6 | Native Rust Is The Default Implementation | `native-rust-default` | cli | Shell is rollback, not peer |
| 7 | The Ledger Owns Derived Task Status | `hooks-own-derived-status` | cli, plugins, vault | Writers that "helpfully" set `[?]`/`[*]` diverge |
| 8 | The Task Line Is The Machine API | `task-line-is-the-api` | projects `^prj`, highlights `^ref` | Stops agents editing YAML status by hand |

**1. Capture Grammar Lives In bob-cli**

- **Claim.** bob-cli is the only implementation of capture grammar, draft
  rewrite, completion data, parse spans, and vault mutation. Bob Mac Capture
  owns presentation, hotkey, process orchestration, and packaging.
  `CaptureCore` talks to `bob` over argv + JSON and imports Foundation only.
- **Rejected.** Parsing in Swift; sharing a grammar crate by copying source;
  plugins reimplementing `@route:id` in the editor.
- **Cost.** Every grammar change is a versioned JSON contract. Older `bob`
  builds degrade in the panel instead of the app papering over them.
- **Reopens when.** Subprocess latency on the hotkey path is the dominant UX
  cost, measured, and a local parse would be a cache of bob-cli's output
  rather than a second grammar.
- **Evidence.** Mac capture README opening paragraph; `sase.yml` linked-repo
  blurb; `BobProcessClient.swift` (`expectedSchema: 1`, 20s timeout, no login
  shell); `docs/capture.md` line 6–8.

**2. Plugins Repo Is The Source Of Truth**

- **Claim.** Bryan-authored plugins are developed in `bob-plugins` under
  `plugins/<id>/` and deployed with `bob plugins sync`. Vault copies under
  `~/bob/.obsidian/plugins/` are deploy targets. `data.json` is never
  overwritten. Dirty vault git files are skipped unless `--force`.
- **Rejected.** Edit-in-vault (the historical state); one git submodule per
  plugin; Obsidian Sync as the plugin transport (it was, and git cannot
  replace that path because the plugins are gitignored).
- **Cost.** A deploy step. The vault is not the working tree.
- **Reopens when.** A plugin is published to the community registry or BRAT,
  which map one id to one repo — then that plugin splits out.
- **Evidence.** plugins README "Development model" / "Deploying"; 
  `docs/plugins.md`; sase.yml; August 2026 git-sync research noting custom
  plugins were a silent Obsidian Sync regression.

**3. Custom Plugins Stay Plain CommonJS**

- **Claim.** `main.js` is the source. No TypeScript, no bundler, no build
  step. `npm test` / `npm run validate` are syntax and helper tests, not a
  compile.
- **Rejected.** The standard Obsidian TS + esbuild plugin template.
- **Cost.** No types, no tree-shaking, no shared compiled package. Six
  personal plugins stay reviewable as the file Obsidian loads.
- **Reopens when.** A plugin is published, or a single `main.js` grows past
  what unbundled review can bear.
- **Evidence.** bob-plugins README "Development model"; `package.json` is
  "repo tooling only (not a bundler)."

**4. Git Is The Only Vault Sync Engine**

- **Claim.** `bob vault-sync` is the only automation path for `~/bob`.
  Obsidian Sync is retired. Exactly one sync engine may be active.
- **Rejected.** Obsidian Sync (quota-failed, then retired); Obsidian Git
  plugin as the engine (needs the GUI, minute-scale, no unattended conflict
  policy); iCloud / syncthing.
- **Cost.** 15s poll latency vs sub-second push; lock sharing; conflict
  copies; `lit_review/` and `xlib/` stay gitignored and need their own
  bridges.
- **Reopens when.** Git sync becomes unreliable across athena / apollo /
  MacBook, or a future Obsidian transport has unattended conflict policy and
  does not ignore `.obsidian/plugins/bob-*`.
- **Evidence.** Home `obsidian.md`; `docs/vault-git-sync.md`;
  `docs/obsidian-sync-exclusions.md` marked historical; research report
  `202608/obsidian_vault_git_sync/`.

**5. Remote Wins; Local Is Quarantined**

- **Claim.** On supported conflicts, remote content stays in place. The
  local version is copied under `_conflicts/` and logged in
  `_conflicts/sync_conflicts.md`. Vault walkers, Tasks global query, and
  Dataview exclude that directory. No `reset --hard`, no force-push, no
  `-X ours/theirs` to clear the vault.
- **Rejected.** Conflict markers in notes (unattended daemons plus Obsidian
  plus `bob nightly` cannot parse `<<<<<<<`); always-ours; interactive
  merge.
- **Cost.** Local work can be quarantined and must be replayed by a human.
- **Reopens when.** Conflict copies pile up unread, or a class of conflict
  appears that remote-wins silently drops irreplaceable local capture.
- **Evidence.** `docs/vault-git-sync.md` "Conflict policy"; the 2026-08-27
  git-sync research called this "the whole project."

**6. Native Rust Is The Default Implementation**

- **Claim.** `bob <subcommand>` runs native Rust. Embedded shell/Perl
  assets remain only as a targeted rollback behind `BOB_CLI_USE_SCRIPT=1`
  for the Pomodoro/notification family. New integrations rely on native
  behavior. Native-only commands have no script path.
- **Rejected.** Keep shell as primary; dual-run parity for every command
  (the sase Python/Rust dispatcher lesson, in miniature).
- **Cost.** Two implementations exist for a shrinking set of commands.
  Tests must still cover the script flag where it is honored.
- **Reopens when.** A remaining shell-only workflow cannot be expressed in
  Rust without shell, and that workflow is still on the daily path.
- **Evidence.** README opening and "Compatibility shims";
  `src/runner.rs`; "New integrations should rely on the native Rust command
  behavior."

This is *softer* than sase's `rust-core-required` (no fallback, no env
switch). Do not pretend they are the same claim. Bob still has an escape
hatch; sase does not.

**7. The Ledger Owns Derived Task Status**

- **Claim.** Today's Pomodoro ledger is the source of truth for Next / In
  Progress / Blocked promotions and structural cleanup.
  `bob task-status-hooks` owns vault-wide Blocked recovery and completed-
  reference retirement. Capture close (`=x`) deliberately leaves those to
  hooks. Other writers (capture, plugins, `projects sync`) must not each
  invent a status policy.
- **Rejected.** Every writer updates checkboxes in the same transaction;
  plugins as the only status engine; capture close fully resolving Blocked.
- **Cost.** The vault can be briefly inconsistent until hooks run. Mac
  cron, nightly, and capture users must leave time for that pass (shared
  `bob_sync.lock`, `--retry-timeout`).
- **Reopens when.** A writer must be transactional with derived status
  because the lag is user-visible corruption rather than a retryable race.
- **Evidence.** `docs/task-status-hooks.md` opening; capture close docs;
  vault-git-sync "Mac scheduled maintenance" ordering.

**8. The Task Line Is The Machine API**

- **Claim.** Humans and agents interact with machine-managed notes through
  a completion-criteria task (`^prj` on projects, `^ref` on Highlights
  reference notes). Commands reconcile frontmatter *from* that task.
  Agents do not hand-edit `status:`, `scheduled:`, or generated `type:` as
  the primary interface.
- **Rejected.** YAML-first project metadata; asking agents to keep
  frontmatter and the task line in sync by hand.
- **Cost.** Extra `bob projects sync` / `bob highlights sync` passes.
  Frontmatter can look "wrong" until sync runs.
- **Reopens when.** A note type has no meaningful task line (pure generated
  indexes) and the task-line convention becomes theater.
- **Evidence.** `docs/projects.md` "This mirrors the `bob highlights` `^ref`
  convention"; highlights "Required parent, type, and ref type."

A useful private rule: if the text would need a rewrite when a flag is

## 6. How to implement (once approved)

This section is implementation guidance for a later authorized memory edit.
This research turn does **not** create the web. `/sase_memory_write`
requires the user's prompt, an approved plan, or an assigned bead to
actually touch `sase/memory/`.

1. **Author the descriptor** `sase/memory/decisions.md` with the frontmatter
   in §2.1 and a preamble that is the sase preamble with "SASE" swapped for
   "Bob" only where needed. Keep the immutability paragraph verbatim in
   spirit. Include empty `<!-- sase:strands -->` / `<!-- /sase:strands -->`
   markers; `sase memory init` fills the roster.
2. **Author eight strand files** under `sase/memory/decisions/` using the
   frontmatter in §2.1 and the four-section body. Put `metadata.status:
   accepted` and `metadata.decided: YYYY-MM-DD`. Add aliases that match how
   agents will search (`sase memory web show decisions grammar`).
3. **Author `[[docs]]` and `[[glossary]]` links** from Why/Cost, not from
   Claim. Link `glossary:pomodoro` / `glossary:task-link` where the word is
   used as a term of art. Link `obsidian.md` from the git-sync strands so
   the home operating note stays canonical for procedure.
4. **Publish** with `sase memory init`. Confirm:
   - `sase memory web list` shows `decisions` / project / 8
   - `sase memory web show decisions` lists eight summaries
   - `sase memory read decisions:capture-grammar-in-bob-cli -r "..."` prints
     Claim/Why/Cost/Reopens
   - `sase doctor` `config.memory_webs` is OK
   - `AGENTS.md` Memory Webs section gained a Decisions subsection *before*
     or beside Glossary, with the roster, and no strand bodies inlined
5. **Do not** add a core note that restates the roster. The descriptor is
   the index.
6. **Do not** add a home web, a `docs/adr/` tree, or xprompt `#memory/`
   entries (web descriptors are not xprompt catalog entries).
7. **Growth rule.** A new strand is justified when (a) an agent violated
   the choice in a real turn, or (b) a proposed change would silently
   reopen an accepted bet. File those as `memory` task beads via
   `/sase_new_task` if the turn is not already authorized to edit memory.

Fail-closed validator reminders (from `sase.memory.web.validation`):

- Web name must not be reserved (`assets`, `README`, artifact kinds).
  `decisions` is free.
- Descriptor must have a sibling strand directory.
- Roster region markers must be well-formed.
- `roster: list` requires per-strand `summary`.
- Normalized keyword/alias/slug collisions inside the web are blockers.
- Cross-scope keyword collisions with a future home web of the same slug
  are warnings; project wins.

There is no CLI writer. Use `$EDITOR` or the TUI Memory panel (`gm`), then
the panel's publish flow / `sase memory init`.

## 7. Recommended solution

Implement a **bob-cli project `decisions` web**, copied from sase's
contract, seeded with the **eight boundary strands in §5.1**, and grown
only under the rule in §6.7.

Keep **home `obsidian.md`** as the vault operating note for every SASE
project. Do not build a home `decisions` web. Do not promote bob-plugins or
bob-mac-capture to SASE projects for memory. Do not convert capture grammar
or plugin keymaps into strands.

That is smaller than the stated plan, and it is the plan I would actually
run. The stated plan's instinct — "record the bets so agents stop
rediscovering them" — is correct. The sase web is the right mold. The
adjustment is to record *bets about the tool stack that launches from this
project*, at the size of the corpus that already exists, and to leave vault
housekeeping where every agent can already see it.

### Why this and not a fat reference note

The corpus already failed as scattered prose: agents have to know which of
README / `docs/capture.md` / plugins README / mac-capture README / home
`obsidian.md` / `sase.yml` to open. A web gives keyword addressing, on-
demand bodies, an always-loaded roster of *names*, and supersession when a
bet is replaced. That is exactly the gap between "we wrote it down
somewhere" and "an agent can `sase memory read decisions:hooks-own-derived-status`
before inventing a status writer."

### Success criteria

- A bob-cli agent working on mac-capture reads strand 1 before adding a
  local parser.
- A bob-cli agent working on a plugin reads strand 2 before editing
  `~/bob/.obsidian/plugins/`.
- A bob-cli agent adding a vault writer reads strand 7 before setting `[?]`
  itself.
- A sase agent creating a note in `~/bob` still gets parent/sync rules from
  home `obsidian.md` without loading Bob's tool-stack roster.
- `AGENTS.md` grows by a roster, not by eight design docs.
