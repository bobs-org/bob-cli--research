## Current implementation map (where the work lands)

### Backend: `bob periods show` builds everything

- Entry: `src/native/periods/report.rs`: `run()` → `execute()` → `build_report()` → `load_daily_metrics()` (one day-grouped `compute()` from `src/native/stats/compute.rs` over the period plus its typical-history window) → `build_facts()` → `build_lanes()` → `build_parts()` (`build_column`, `build_child`, `build_groups`).
- `FACT_IDS = ["worked", "reviewed", "done", "created", "review_closed"]`; `visible_fact_ids()` drops anything in `stats.hide` (see `src/native/config/stats.rs`: `StatsConfig { range, overview, hide, since, user_metrics, path }`). The strip therefore already respects `stats.hide`; any new lane work must keep that invariant (a hidden `worked` means no lanes at all).
- `build_lanes(id, span, today, daily, homes, theme_hues)`:
  - `roots` = `aggregate.parts["root_parent"]` with fallback to `parts["area"]` (older-bob compatibility); `root_rows = lane_rows(roots, total, homes, None)`.
  - `themes` = `aggregate.parts["theme"]`; when `!matches!(id, PeriodId::Week { .. })` (`types_folded = true` for quarter/year/all-time), it folds `(unnamed)` and every theme under 2% of Worked into `other`. Week lanes are unmodified.
  - Sorting is deterministic: `lane_rows()` filters `value > 0` and sorts by `value desc, key asc`. Labels resolve via `theme_hues[normalize(key)].name` for themes, else `homes[key].label`, else the raw key.
  - Contract in `docs/periods.md` ("Period reports"): `lanes.root_parent` and `lanes.theme` each carry `{key, label, minutes, display, share}` rows plus a type-fold flag. `columns[].stack` carries per-child root-parent `{key, minutes}` entries; `children[].mostly` carries top-3 root shares.
- Typical lines: `build_typical()` uses 4 prior periods for week/quarter, 3 for year, none for all-time; needs ≥2 usable priors or it renders `typical –`. Closed periods get `relation` (`above`/`below`/`equal`); open ones never mark. This is why the Q3 screenshot shows `typical –` everywhere (insufficient usable history at this range, not a bug in the strip).
- Config today: `src/native/config/stats.rs` (`parse_stats_value()`) only accepts `range`, `overview`, `hide`, `since`, `metrics`. There is no `stats.day_strip`, no `stats.strip.*`, and no top-N key anywhere in `bob-cli`. The documented `stats.day_strip` toggle in `docs/stats.md` ("Controls: `stats.day_strip` in `~/.config/bob/config.yml`") is plugin-side only (see below); the Rust config would reject it as unknown if placed under `stats:` depending on strictness, so a new top-N key needs an explicit backend change plus `just docs-gen`/`docs-check` updates.

### Frontend: the period strip already shares the day-strip lane switch

- `bob-plugins/plugins/bob-ledger-tools/src/239-plugin-period-strip-fence.js` (`BobLedgerToolsPeriodStripMixin::periodStripPaint`) reads the lane view from `dayStripLaneViewCurrent()` and passes `laneView` into `periodStripModel(report, periodId, { laneView, fetchedView, themeHueFor })`. Its `cycleLanes` handler calls `dayStripCycleLaneView({})`. In other words, the requested toggle already exists and is shared: cycling the day strip cycles every period strip on the device and vice versa.
- `239-plugin-period-strip-model.js::periodStripModel()` builds `roots = periodStripLane(report, "root_parent", ctx)` and `themes = periodStripLane(report, "theme", ctx)`, then `lanes = dayStripLaneLayout({ state, mix: { ...roots }, themes, view: laneView })` — the exact same layout helper as the day strip (`239-plugin-day-strip-lanes.js::dayStripLaneLayout`, views `"both" | "roots" | "themes"`, `shown`, `switchable`, `next`, `title`, `ariaLabel`). `periodStripRenderMix()` slices each legend to 3 entries plus a `+N` overflow counter; the bar itself keeps every segment (`flex-grow` ∝ minutes).
- Shared builders in `239-plugin-time-lanes-model.js`: `timeLaneRootSegments()` (hue-slot order, then label, then muted roots, buckets last; `@unlinked`/`@unfiled` stay gray; `tone` = `hue|gray|none` with `none` = diagonal hatch), `timeLaneThemeSegments()` (coloured by minutes desc then label; gray for exempt/unconfigured/gray-area names/`(unnamed)`/`other`; same-hue collisions shaded 100%/65%/42%), `timeLaneLegend()` (bar order, lowest-ranked drop first, `overflowDefault = len − 3`).
- Columns vs lanes: `periodStripWeekColumns()` / `periodStripParts*` always stack root parents, independent of `laneView`. So today "both" means two lane bars (roots + types) over root-stacked columns; "roots" hides the type lane but columns stay roots; "themes" hides the root lane but columns still show roots. There is no types-stacked column mode.
- Persistence: `239-plugin-day-strip-lanes.js` stores one global `bob-ledger-tools-day-strip-bars` via `app.loadLocalStorage/saveLocalStorage` (in-memory fallback, device-local, never written to the note). The period strip has no separate key.
- Previews: `scripts/preview-period-strip.cjs` (matrix: current/closed/pre-ledger/future week + quarter/year/all parts fixtures) and `scripts/preview-day-strip.cjs` render production CSS/JS in headless Chromium; `scripts/fixtures/stats/README.md` explains regenerating `canonical.json` from the golden vault with pinned `BOB_NOW`.
- `docs/` ownership: `docs/stats.md` owns the Day-strip contract (facts, typical, lanes, switch, states); `docs/periods.md` owns the period report JSON contract and briefs; `docs/pomodoro-homes.md` owns root-parent derivation and hue rules; `docs/dashboard.md` links the strip family. Per `sase/memory/docs.md`, a behavior change updates the contract/reference page plus only the guide steps it invalidates, and `just docs-check` gates.

## Critique: is this a good idea?

Yes, with three corrections. The clutter diagnosis is correct, but two of the four bullets need reframing and one already exists.

1. "Only use task types in the current charts" — directionally right, literally risky. The Q3/year evidence shows why: quarter/year type lanes today are dominated by the folding bucket (`other 85%` in Q3, `76%` in 2026). If "current charts" means the lane bars, switching them to types-only just trades nine-root clutter for a giant gray `other` bar on every quarter/year/all-time note — strictly uglier and less informative. If it means the stacked columns, switching 13/53 week columns from root stacks to type stacks is worse: it breaks the hue link between columns, lanes, and the parts table (`children[].mostly`, `columns[].stack` are all root-keyed), and it destroys the weekly-review question the columns answer ("which home dominated each child?"). Keep columns root-stacked; fix the lanes instead.
2. "Separate root-parent chart with top N" — good idea, and N=5 fits the data. W45's top 5 roots cover ~97% of Worked; Q3's top 5 cover ~99%; even 2026's 16 roots collapse to 5 + `Other` without losing the story. The remainder must aggregate into an `Other` bar segment (so bars still sum to the Worked total), not vanish: vanishing breaks `share` math, screen-reader sentences, and the "bars always sum" invariant both strips rely on (`summarize_parts` skips provisional today; tiles and lanes agree because they share the same `worked` parts).
3. "Top N configurable, set to 5 in chezmoi" — right place, wrong layer if done plugin-only. `home/dot_config/bob/config.yml` is the only synced, host-independent config surface (the lane view in `localStorage` is deliberately device-local). But plugins never read `config.yml` directly; they spawn `bob periods show -f json`. So N must be implemented in Rust (`build_lanes` + `build_parts` stacking keys) and shipped in the JSON (capped rows + explicit `other` + `truncated` metadata), with the plugin only laying out what it is given. A plugin-only `slice(0, 5)` would desync `bob periods show` consumers (briefs, `dash_stats`, Mac capture) and produce different totals per client.
4. "Toggle roots / types / both like the day strip" — already exists; do not rebuild it. The period strip reuses `dayStripLaneLayout` and `dayStripCycleLaneView`, with the same `●`/`■` switch, keyboard (`Enter`/`Space`), tooltips, `aria-label`s, and 160 ms fade. What is missing is discoverability and a decision about scope: today the view is global and shared (one `bob-ledger-tools-day-strip-bars` key for day + all period strips). The request should be read as "keep and expose that toggle on period strips" (bigger hit target, visible affordance, documented in `docs/periods.md`), not "build a new toggle".

Beauty note: the current period lanes row is the ugliest element in the screenshot because it shows two legends + two bars + meta text + switch on one wrapping row with independently fitting legends (`periodStripRenderMix` slices each legend to 3 + overflow). Once lanes are capped server-side to 5 + `Other`, each legend typically fits without overflow on week/quarter notes, and the row reads as two calm 6 px bars (roots first, types second, per the Stats-page order) rather than a wall of dots.

## Alternatives considered (and why they lose)

- A. Plugin-only `slice(0, N)`. Tempting (one-file change in `periodStripLane`), but every `bob periods show` consumer would disagree: `bob periods brief` Time section lists every root ≥5% plus folded types, `dash_stats` renders the full panel, and Mac capture delegates to the same `bob` subprocess JSON. Server-side capping keeps one truth; client slicing creates two.
- B. Separate period lane-view key (`bob-ledger-tools-period-strip-bars`). Cleaner mental model (day and period views independent), but it doubles the gesture surface (two switches, two commands, migration of the existing shared key) for little gain: Bryan's typical use is "focus one dimension everywhere today". Keep the shared view; if later evidence shows day/period views diverging in practice, split then with a logged migration.
- C. Columns follow the lane view (roots view → root stacks, types view → type stacks). Faithful to "toggle changes the charts", but columns are navigation (click opens the child note; `Alt+Enter` opens Stats pinned to that child) and their hues must match the parts table and the lanes. Re-hueing 53 year columns per toggle press causes layout thrash and breaks the "hues come from one catalog" rule (`timeLaneRootSegments`/`timeLaneThemeSegments`). Keep columns root-stacked always; the toggle governs the two lane bars only.
- D. Hide the remainder instead of an `Other` segment. Saves ~one segment of bar width, but the bar no longer sums to Worked, `share` percentages stop adding to 100%, and keyboard/screen-reader users lose the existence of the long tail. The day strip gets away with `+N` because a day has few roots; a quarter/year needs the honest `Other` (gray, `tone: gray`, title lists folded keys).

## Adjustments to the requirements (explicit)

1. Reinterpret "only use task types in the current charts" as "the lanes row shows at most two calm bars — roots and types — each capped, with the toggle choosing which are visible; the stacked columns stay root-parent stacks." Do not convert columns to types.
2. Cap roots server-side at N (default 5) plus one synthesized `other` row (`key: "other"`, gray tone, `share` of folded minutes, title lists folded labels). Cap applies to `lanes.root_parent` and to the stacking keys used in `columns[].stack` / `children[].stack` (columns keep full heights; only stack keys fold). Do not cap `lanes.theme` by N; instead fix the existing 2% fold so quarters/years are readable (see recommendation).
3. Keep the existing shared `both/roots/themes` toggle; scope this work to exposing it on period strips (hit target ≥24 px, visible focus ring, `Cycle period bars` command palette entry, documented in `docs/periods.md`). Do not build a second toggle system.
4. Apply the design to all four period kinds at once (week/quarter/year/all-time share `periodStripModel` and `build_lanes`), but tune per kind: weeks keep unfolded types; quarters/years keep the fold but raise its floor and always show the same top-N roots.
5. Set N=5 in chezmoi only after the code accepts the key with validation and a sane default; never hand-edit generated JSON or plugin fixtures to fake it.

## Recommended solution

### Data contract (Rust, `bob-cli`)

1. New config key `stats.strip.top_roots` (integer 1–20, default 5). Parse in `src/native/config/stats.rs::parse_stats_value` alongside `range/overview/hide/since`; invalid values fall back to 5 with a warning everywhere except `bob periods show`, which exits 2 like other `stats.*` config errors (follow `parse_range`/`parse_since` precedent). Document in `docs/stats.md` and `docs/periods.md`; regenerate CLI/reference docs with `just docs-gen`. Rationale for the name: it lives under the existing `stats:` block, mirrors `plan.max_*` lane-cap naming, and avoids inventing a parallel `period_strip:` top-level block.
2. `src/native/periods/report.rs::build_lanes`: after `lane_rows(roots, …)`, keep the top N rows by `(minutes desc, key asc)` and fold the rest into one `other` row (`minutes` = sum, `display = format_minutes(sum)`, `share = percent(sum, total)`). Emit `lanes.root_parent_top_n = N`, `lanes.root_parent_truncated = bool`, and `lanes.other_keys = [folded labels]` (for tooltips/a11y). Keep `types_folded` semantics, but change the quarter/year theme floor from "under 2% → other" to "keep top 5 themes + other" so Q3 stops rendering `other 85%`: same helper, same `other` shape, deterministic order. Weeks stay unfolded (no behavior change when roots ≤ N and themes are few).
3. `build_parts`: reuse the capped root key set for `columns[].stack` and `children[].stack`/`mostly` so columns, lanes, and the parts table agree; column heights and Worked values are unchanged (only stack keys fold into `other`). `build_facts`, `build_typical`, `groups`, and `homes`/`theme_hues` catalogs are untouched.
4. JSON stays schema 1 (additive fields only). `bob periods show -f json` golden tests in `tests/` plus `tests/fixtures/periods/scaffold-*.md` gain top-N cases (week with >N roots, quarter with folded types, year with 16 roots → 5 + other).

### Rendering (plugins, `bob-plugins`)

5. No new toggle: keep `dayStripLaneViewOf` / `dayStripLaneLayout` / `dayStripCycleLaneView` shared between `239-plugin-day-strip-*` and `239-plugin-period-strip-model.js`. In `239-plugin-period-strip-render.js::paintPeriodStrip`, enlarge the switch hit target, keep `role="button" tabindex="0"` + `Enter`/`Space`, keep the `●`/`■` marks and `title`/`aria-label` copy, and add a `Cycle period bars` command (same action as `Cycle Day stats bars`) so the gesture is discoverable without a mouse.
6. `periodStripLane()` needs no N logic (server already capped); keep `timeLaneLegend`'s 3-label fitter for narrow notes, but with N=5 + other the legend usually fits. `Other` renders gray (`tone: gray`, never hatched; hatch stays reserved for `none`: `@unlinked`/`@unfiled`/`(unnamed)`), title = `Other · <display> · <share>` plus folded labels, keyboard stop opens Stats on the `homes`/`themes` panel as today.
7. Layout per `docs/stats.md` family rules: roots lane first, types second; one 6 px fully-rounded bar per visible lane, 2 px page-background gaps, `min-width: 2 px`; legend `0.85em` muted + `--text-normal` tabular values; meta text (`so far · HH:MM` / coverage / `since …`) right-aligned on the first shown lane; 160 ms fade when the view changes on the same period; skeleton keeps two empty tracks. No cards, borders, backgrounds, or `<button>` elements (spans with `role="link"`/`role="button"`, `mousedown` never steals focus so vim keeps working).
8. Columns: unchanged interaction (click opens child note, `Alt+Enter` opens Stats pinned to that child, roving `tabindex`, `←/→/Home/End`); restacked colors come from the same capped key set so lanes ↔ columns ↔ parts table share one hue assignment per strip.

### Config + docs + verification

9. Chezmoi: after the code lands, set `stats.strip.top_roots: 5` in `home/dot_config/bob/config.yml` (linked `chezmoi` repo) — the single intent of the parenthetical in the request. No other chezmoi change (no plugin `localStorage` seeding; device view stays local by design).
10. Docs: `docs/periods.md` gains the lanes contract (`top_roots`, `other`, `types_folded` v2 rule, toggle behavior, per-kind columns) and `docs/stats.md` gains the shared switch + `stats.strip.top_roots` control; run `just docs-check` (and `just docs-gen` if CLI help changes).
11. Tests/previews: Rust unit + golden tests for top-N folding (deterministic tie-break `minutes desc, key asc`), `stats.hide=worked` (no lanes), empty/future/missing states, and hue stability; plugin `test-ledger-tools-period-strip*` + `preview-period-strip.cjs` matrix (week/quarter/year/all × light/dark × narrow/wide) reviewed pixel-side before landing. The release rides the daily train (per `decisions:bob-cli-releases-ride-a-daily-train`): no version/CHANGELOG edits by the agent.

### Acceptance (what "done" looks like)

- `2026-W45` shows ≤6 root segments (5 + Other only when needed) and ≤6 type segments; `2026-Q3` no longer shows `other 85%` as the type story (top 5 types + other); `2026` (16 roots, 53 columns) shows 5 + Other with full column heights.

- `bob periods show <week|quarter|year|all> -f json` totals still reconcile (roots sum = themes sum = Worked; `other` included), and `bob periods brief` Time section matches the capped lanes.

## Risks and open questions

- The screenshot's quarter has `typical –` on all five facts (short history at this range). Capping lanes will not fix that; if Bryan expects typicals on quarters, that is a separate `build_typical` window question, not strip work.
- If Bryan actually wants columns re-stacked by type (not just lanes), say so explicitly: it forks the hue catalog, doubles legend work, and needs a second `stack` dimension in the JSON. I recommend against it for the reasons in §Critique-1/C.
- N=5 is a display cap, not a data loss: folded roots remain queryable via `bob stats show` and `dash_stats`. If the long tail matters weekly (e.g. many 1% homes), raise to 8 rather than removing the cap.
