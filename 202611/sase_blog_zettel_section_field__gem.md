# Adding `record.section` to `~/bob/sase_blog_zettel.md`: Implementation Research, Critique, and Recommended Schema

## Bottom Line

**Yes — add `record.section` to `~/bob/sase_blog_zettel.md`, paired with one closely related field (`record.subsection`) and an upgraded `~/bob/sase_blog_zettel.base` storyboard.**

Bryan's Nov 14 creation of `[[sase_blog#^section-field]]` exposed a real gap in the Nov 12 schema: `part` (`hook`, `why`, `what`, `why_not`, `close`) describes *rhetorical role*, not *post destination*, and Obsidian Bases cannot group records by which heading inside `~/bob/sase_blog_contents.md` links to them (`file.backlinks` is file-level only). When `prompt_management_macros.md` was captured on 2026-11-14 with `part: why`, `part` alone could not indicate that it belongs under **What is SASE? → Prompt language (macros)**.

However, implementing the request naively introduces five avoidable traps verified directly in `bob` (`v0.5.0`), `bob-mac-capture`, and `sase` HEAD:

1. **Flat choices vs. 2-level outline:** `^section-field` has 4 top-level sections, with **8 nested subsections** inside `What is SASE?`. Bob `choices` fields are strictly flat. Putting only top-level sections in `section` collapses ~70% of the essay into one bucket; flattening all 12–14 items into `section` overflows `RecordCardView`'s single-line choice pill strip (`schemaChoiceCapsules`). Splitting **`section` (top-level sections)** and **`subsection` (the nested topics)** solves both cleanly.
2. **Choice-key immutability:** `bob albums update` and the Obsidian Schema Card forbid renaming stored choice keys (`choice_rename_prohibited`) and refuse deleting any choice with `count > 0` (`choice_used`). Using `bob albums update` (`field.add`) auto-derives brittle keys like `why_sase_is_still_not_ready`. Authoring the YAML directly lets you pair **short, stable keys** (`why_not_ready`, `macros`, `gate`) with **freely editable labels**.
3. **Incomplete source outline & stale term:** `^section-field` (`16:07 — Write some sections in this task`) omits an opening **Introduction** and a closing **Conclusion** (both already present in `sase_blog_contents.md` and `sase_blog.md`), and uses `"agent families"`, which `sase/docs/reference/glossary.md` notes was renamed to **Sase Agent Session** (`--<suffix>` chains).
4. **`[!records]` index illusion:** In `bob`, `status` always owns top-level grouping when present (`grouping.rs:191`). Verified empirically: setting `index_by: section` triggers only past 12 records in a status group, prints **raw choice keys** (`future_work`, `what_is_sase`) instead of labels, and sorts **alphabetically** rather than in narrative order. Narrative-ordered grouping belongs in **`sase_blog_zettel.base`** via Base formulas, not `index_by`.
5. **Productive-procrastination risk:** `sase_blog.md` is five months old (`2026-06-11`), `sase_blog_contents.md` still has 15 `TODO` stubs, `sase_blog_zettel/` has only 1 seed with **0 words of prose**, and the Nov 12 research/guides remain unread (`wip` / `queued`). Schema work must end in one edit and immediately transition to drafting `## Draft` prose.

## Critique of the Plan

### What Is Strong About the Plan

1. **The Nov 12 "no `section` field" prohibition was over-strict for the actual drafting workflow.**
   The Nov 12 synthesis assumed `sase_blog_contents.md` links (`→ [[sase_blog_zettel/<stem>|Title]]`) would track section assignment. In practice, Obsidian Bases cannot inspect *which heading* in `sase_blog_contents.md` links to a record (`file.backlinks` only returns file links), and manually editing the spine for every raw seed capture adds friction. A `section` property lets `sase_blog_zettel.base` answer *"which sections have zero seeds or drafts?"* immediately.
2. **The outline inside `^section-field` is much stronger than `sase_blog_contents.md`.**
   Reframing the body around 8 reader-centric `"What is a ...?"` primitives (`macros`, `agent turn`, `gate`, `sessions/clans/tribes`, `memory`, `plan + artifacts`, `project`, `automation`), followed by `The Demos`, `Why SASE is still NOT ready?`, and `Future Work`, explains SASE as a cohesive model rather than a tour of internal subsystems.
3. **Album-owned fixed values leverage Bob's best completion UX.**
   Putting `values:` in `sase_blog_zettel.md` gives instant candidate pills and substring completion on both key and label in Bob Mac Capture even while the folder has only 1 note (whereas `suggest: true` starts completely empty).

### Real Risks & Weaknesses

1. **Tooling-as-avoidance risk (highest risk):**
   `sase_blog` has had 4 outline iterations since June, 15 empty `TODO`s in `sase_blog_contents.md`, and 1 zettel with 0 words of draft prose. Tuning schemas and researching them can keep substituting for dictating the first 150-word zero-drafts.
2. **Outline volatility vs. fixed choice keys:**
   You noted *"a fixed set of values (that I could always change by modifying the `~/bob/sase_blog_zettel.md` file)"*. Editing YAML works for adding choices or changing display labels/emojis, **but** removing or renaming a stored choice key breaks every existing record pointing at it (`record_invalid_value` in `bob records check`) until each record's frontmatter is rewritten. Choice keys must be short, stable concept slugs — never full heading sentences.
3. **2-level structure vs. Bob's flat choice model:**
   `^section-field` explicitly marks 8 items as subsections of `What is SASE?`. Bob has no nested choice schema and no conditional field validation (so a `subsection` field cannot restrict its candidates based on `section`).
4. **Two competing outlines in `~/bob`:**
   Right now `^section-field` describes one outline while `sase_blog_contents.md` still holds an incompatible 15-section outline (`§1`–`§4`) and `^zd-*` tasks reference `§1.1`, `§1.3`, `§1.3.2`, `§1.5`. Leaving both un-reconciled will create confusion the moment you start assembling prose.
5. **`[!records]` index limits:**
   Because `status` groups `[!records]`, and `index_by: section` renders raw keys in alphabetical order past 12 items, the album note's own Markdown callout will never look like an essay outline. Only `sase_blog_zettel.base` (with Base formulas) can group and sort zettels in blog-section order.

## Justified Requirement Adjustments

Clearly calling out every departure from a literal transcription of the prompt and `^section-field`:

1. **Add `intro` (`🪝 Introduction`) and `close` (`🏁 Conclusion`) to `section`:**
   `^section-field`'s work log says `"Write some sections in this task"`, and it lists only body/ending chapters while omitting the post opening (already partially drafted in `sase_blog_contents.md` and tracked in `^intro-v1`) and closing/polls (`^need-your-help`, `## 4. Conclusion`). Including `intro` and `close` prevents shoehorning opening/closing claims into `what_is_sase` or `future_work`.
2. **Add one related field, `record.subsection` (`choices`), for the 8 nested `What is SASE?` bullets:**
   Putting `What is SASE?` alone in `section` hides 8 distinct technical primitives inside one giant bucket; flattening all 14 headings into `section` breaks `^section-field`'s explicit `NOTE: All of the below sub-bullets should be subsections of this section.` Adding `subsection` keeps `section` clean (6 values) while preserving exact targeting.
3. **Update `"agent families"` → `sessions` in the display label (keeping choice keys decoupled from headings):**
   In `sase` HEAD (`docs/reference/glossary.md:576`), *agent family* was renamed to **Sase Agent Session** (alongside **Agent Clan**, **Agent Tribe**, and **Agent Hood**). Using key `sessions_clans_tribes` and label `👥 Sessions, clans, and tribes` keeps the essay current (you can still explain the historical `families` rename in the prose). Likewise, use short stable choice keys (`why_not_ready`, `macros`, `agent_turn`, `gate`, `memory`, `plan`, `project`, `automation`, `demos`, `future_work`) rather than auto-derived keys like `why_sase_is_still_not_ready`.
4. **Keep both `section` and `subsection` optional (`required: false`):**
   `sase_blog_zettel.md` covers *"my SASE posts"* (plural) and includes `status: later` (future posts) and `status: cut`. Requiring `section` would make `bob capture` exit `2` on raw fleeting ideas or `⏭️ Later` zettels unless a dummy `unplaced` value were added.
   *Trade-off disclosed:* Because `CaptureRecordPresentation.swift` hides unset optional rows under `More`, `section` and `subsection` won't appear in Bob Mac Capture's default visible rows until you type `- section:: ` (or use the `- ` field menu). If you strongly prefer `Tab`-guided prompting (`next_missing_field`) for `section` on every capture, set `required: true` on `section` and add `unplaced: 📥 Unplaced` as an explicit choice — with the caveat that `unplaced` can never be removed while any record uses it.
5. **Change `index_facets` to `[section, subsection, claim]`; do NOT set `index_by: section`:**
   Bob caps `index_facets` at 3 fields (`albums/mod.rs:232`). Keeping `[section, subsection, claim]` ensures the `[!records]` index displays target section + subsection + one-sentence claim. Leave `index_by` unset because `index_by: section` renders raw choice keys alphabetically past 12 items (`future_work` before `what_is_sase`). Put section-ordered grouping into `sase_blog_zettel.base` instead.
6. **Reconcile `sase_blog_contents.md` when ready, and keep `sase_blog_zettel` free of extra workflow fields:**
   When you commit to the `^section-field` outline, update the headings in `sase_blog_contents.md` so the spine and `sase_blog_zettel.md` agree on one outline.

## Recommended Solution

### 1. Update `~/bob/sase_blog_zettel.md` Frontmatter

Edit `~/bob/sase_blog_zettel.md` directly in YAML (rather than `bob albums update`, which cannot edit `index_facets` and auto-derives verbose keys like `why_sase_is_still_not_ready`):

```yaml
---
parent: "[[sase_blog]]"
type: "[[album]]"
summary: Topic-sized pieces of my SASE posts, one claim per record, in my own voice.
emoji: 📇
created: 2026-11-12T13:54:08-0500
index_facets: [section, subsection, claim]
record:
  noun: zettel
  label: Zettel
  dated_notes: true
  fields:
    status:
      required: true
      values:
        seed: 🌱 Seed
        draft: ✍️ Draft
        ready: ✅ Ready
        placed: 📌 Placed
        later: ⏭️ Later
        cut: ✂️ Cut
    claim:
      required: true
    section:
      values:
        intro: 🪝 Introduction
        what_is_sase: 🧱 What is SASE?
        demos: 🎬 The Demos
        why_not_ready: 🚧 Why SASE is still NOT ready?
        future_work: 🔭 Future Work
        close: 🏁 Conclusion
    subsection:
      values:
        macros: ⌨️ Prompt language (macros)
        agent_turn: 🔄 Agent turn
        gate: 🚦 Gate
        sessions_clans_tribes: 👥 Sessions, clans, and tribes
        memory: 🧠 Memory
        plan: 🗺️ Plan (and artifacts)
        project: 📁 Project

      values:
        hook: 🪝 Hook

        why_not: 🛑 Why not
        close: 🏁 Close
---
```

*(Note: Once `section` and `subsection` exist, you can still use the Obsidian Schema Card `⊞ Schema` / `bob albums update` to add new subsections, reorder choices, or tweak emojis/labels without breaking existing keys.)*

### 2. Upgrade `~/bob/sase_blog_zettel.base` Into an Outline-Ordered Storyboard

Because Bob's `[!records]` callout groups by `status`, `sase_blog_zettel.base` is what turns `section` + `subsection` into a live, reading-order dashboard (following the same formula pattern used in `~/bob/refs.base` and `~/bob/movies.base`):

```yaml
filters:
  and:
    - file.inFolder("sase_blog_zettel")
    - note.type == link("record")
formulas:
  name: if(title, file.asLink(title), file.asLink())
  status_label: if(status == "seed", "🌱 Seed", if(status == "draft", "✍️ Draft", if(status == "ready", "✅ Ready", if(status == "placed", "📌 Placed", if(status == "later", "⏭️ Later", if(status == "cut", "✂️ Cut", status))))))
  section_slot: if(section == "intro", "1. 🪝 Introduction", if(section == "what_is_sase", "2. 🧱 What is SASE?", if(section == "demos", "3. 🎬 The Demos", if(section == "why_not_ready", "4. 🚧 Why SASE is still NOT ready?", if(section == "future_work", "5. 🔭 Future Work", if(section == "close", "6. 🏁 Conclusion", "9. 📥 Unassigned"))))))
  subsection_slot: if(subsection == "macros", "1. ⌨️ Prompt language (macros)", if(subsection == "agent_turn", "2. 🔄 Agent turn", if(subsection == "gate", "3. 🚦 Gate", if(subsection == "sessions_clans_tribes", "4. 👥 Sessions, clans, and tribes", if(subsection == "memory", "5. 🧠 Memory", if(subsection == "plan", "6. 🗺️ Plan (and artifacts)", if(subsection == "project", "7. 📁 Project", if(subsection == "automation", "8. ⚙️ Automation (service)", ""))))))))
properties:
  formula.name:
    displayName: Zettel
  formula.status_label:
    displayName: Status
  formula.section_slot:
    displayName: Section
  formula.subsection_slot:
    displayName: Subsection
  note.part:
    displayName: Part
  note.claim:
    displayName: Claim
views:
  - type: table
    name: "🧭 By Section"
    filters:
      and:
        - status != "later"
        - status != "cut"
    groupBy:
      property: formula.section_slot
      direction: ASC
    order:
      - formula.name
      - formula.subsection_slot
      - formula.status_label
      - claim
      - part
    sort:
      - property: formula.subsection_slot
        direction: ASC
      - property: formula.name
        direction: ASC
    summaries:
      formula.name: Count
  - type: table
    name: "📇 By Status"
    groupBy:
      property: formula.status_label
      direction: ASC
    order:
      - formula.name
      - formula.section_slot
      - formula.subsection_slot
      - claim
      - part
    sort:
      - property: formula.section_slot
        direction: ASC
      - property: formula.subsection_slot
        direction: ASC
      - property: formula.name
        direction: ASC
    summaries:
      formula.name: Count
  - type: table
    name: "📥 Needs Section"
    filters:
      and:
        - status != "later"
        - status != "cut"
        - "!section"
    order:
      - formula.name
      - formula.status_label
      - claim
      - part
    sort:
      - property: formula.name
        direction: ASC
    summaries:
      formula.name: Count
```
